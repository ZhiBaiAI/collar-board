# collar-changelog — 变更时间线记录员

## 定位

六个 Skill 里**自动化程度最高**的一个：完全被动，由 git commit 触发，无需人提醒。
它回答一个问题：**这个项目是什么时候、变成了什么样。**

> 「所有知识必须版本化落到仓库文件里，一旦发生就自动沉淀进 docs/，
> 下一个会话或下一个人拉取仓库就能获得完整上下文。」

## 触发方式

| 类型 | 时机 |
|---|---|
| 被动（**强制**） | git commit —— 提交关卡三件事之一 |
| 主动 | 用户要发版说明 / 月度回顾 / 问「XX 是什么时候改的」 |

**强制是真强制**：知识沉淀从「靠自觉」变成「流程门禁」，
杜绝「这次先算了、下次一定」的滑坡。一旦开始欠账，知识库很快就会烂掉。

## 执行步骤

### Step 1 — 采集本次提交事实

- 提交哈希、作者、时间、commit message
- 变更文件列表（区分 新增 / 修改 / 删除 / 重命名）
- 关联的 spec 坐标（从路径反查 `docs/specs/` 认领表）

**「谁改的」是第一线索**——多人协同排查时，作者信息必须保留。

### Step 2 — 分类（一眼看懂改动性质）

| 标签 | 含义 |
|---|---|
| `feature` | 新功能、或稳定功能的正式迭代 |
| `patch` | 补丁式小改动 |
| `sunset` | 功能下线 / 迁移 |
| `refactor` | 结构重组，行为不变 |
| `fix` | 缺陷修复 |
| `chore` | 依赖、配置、文档等杂项 |
| `BREAKING` | 破坏性变更（**必须加粗置顶**，commit message 用 `!` 后缀表达） |
| — | commit-msg 放行但上表未列出的类型（docs/test/ci/build/perf/style/revert）归 `chore` |

### Step 3 — 落盘

路径：`docs/changelog/YYYY/YYYY-MM.md`（按月聚合，跨月自动开新文件）

单条格式：

```markdown
### YYYY-MM-DD · ⟨标签⟩ · ⟨一句话概述⟩ · ⟨@作者⟩

- **Spec**：[⟨坐标⟩](../../specs/…)  ｜ **影响面**：⟨模块/接口/数据⟩
  <!-- 链接基准 = 月度文件位置 docs/changelog/YYYY/，所以是 ../../specs/ -->
- **变更**：⟨做了什么，写结果不写过程⟩
- **破坏性**：⟨有/无；有则写清迁移方式⟩
- **关联**：⟨PR / Issue / ADR⟩
```

### Step 4 — 反向提醒（不代做，只提示）

- 改动涉及**接口签名 / 数据字段 / 共享配置** → 提示「跨模块影响，建议同步 `collar-architecture` 检查」
- 改动落在**未认领区域** → 提示 `collar-specs` 认领
- 出现**破坏性变更** → 提示在 `docs/runbook/` 补迁移说明

### Step 5 — 月度回顾（主动触发时）

按月聚合输出：本月各业务域改动分布、破坏性变更清单、sunset 清单、Spec 偏离高发区。
这些趋势反哺 `collar-architecture`（是否该重构）与 `collar-runbook`（是否该立约定）。

---

## 护栏

- ❌ 不写「优化了一些代码」这种无信息量的描述——**写结果，不写过程**
- ❌ 不遗漏作者（多人协同第一线索）
- ❌ 不把同一件事记两遍（一次提交 = 一条记录）
- ❌ 改写历史条目——时间线只增不改，更正用新条目
- ❌ 写会话指代词（S7 门禁按词表拦截，词表见 `scripts/collar-check.sh`）
- ✅ 破坏性变更必须显眼，附带迁移方式
- ✅ 每条尽量能反查到 spec 坐标，让时间线和站点地图互相索引

Next: 落盘后随提交进 `pre-commit` 门禁（S6 强制同次提交）；月度回顾先 `collar-status.sh --specs` 对齐坐标。

## 与其他 Skill 的协作

提交关卡上三个 Skill 同时工作，各管一个正交维度：
- `collar-changelog` 记**做了什么**（本 Skill）
- `collar-runbook` 抽**学到了什么**
- `collar-specs` 检**代码是否偏离了意图**

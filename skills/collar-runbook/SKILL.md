# collar-runbook — 过程知识沉淀者 + 入口地图守卫

## 定位

回答一个问题：**这个项目有哪些「踩过坑才知道」的知识。**
这类知识不写在任何代码里，但对 AI 的价值最高——它决定了 AI 会不会重蹈覆辙。

## 触发方式

| 类型 | 时机 |
|---|---|
| 被动 | git commit —— 从提交与对话记录中抽取约定与坑（提交关卡三件事之一） |
| 主动 | 用户说「记住这个」「以后都这样」「这是个坑」 |
| 守卫 | 每次写入 `AGENTS.md` 前后，检查行数 |

---

## 职责一：沉淀三类过程知识

落盘位置按类型分流：

| 类型 | 去哪 | 说明 |
|---|---|---|
| **强约定** | `docs/runbook/conventions.md` | 全项目必须遵守的规则，违反即拦截 |
| **环境差异** | `docs/runbook/environments.md` | 预发 / 线上 / 本地的差异，隐藏地形 |
| **排障剧本** | `docs/runbook/troubleshooting.md` | 现象 → 根因 → 解法 → 复盘 |
| **测试知识** | `docs/runbook/testing.md` | 测试知识总入口：分层口径 / 运行时机 / 冒烟清单 / 测试坑 |
| **通用过程知识** | `docs/runbook/README.md` 下的索引条目 | 不属于以上四类的零散经验 |

> `testing.md` 是**跨功能点**测试知识的落点；**单个功能点**的测试点写在
> 该功能点目录下的 `tests.md`（spec 的伴生文档，由 `collar-specs` 维护）。
> 判据：**这条知识换一个功能点还成立吗？成立 → testing.md，不成立 → 该功能点的 tests.md。**

条目格式（四段式，缺一不可）：

```markdown
## ⟨一句话结论⟩

- **现象**：⟨看到了什么⟩
- **根因**：⟨为什么会这样⟩
- **结论**：⟨以后该怎么做 / 该避开什么⟩
- **证据**：⟨提交哈希 / 日期 / 相关文档链接⟩
```

**没有「结论」的条目不许入库**——只记录现象不提炼规则，等于制造噪音。

---

## 职责二：守卫 AGENTS.md（硬性）

`AGENTS.md` 是 Agent 的唯一入口，**每个会话必加载，所以它只导航、不堆细节**。

守卫规则：
1. 当前行数 **> 115 行** → 立即触发迁出：把细节搬到 `docs/` 对应模块，
   `AGENTS.md` 只保留**一行摘要 + 链接**。
2. 检查是否有「可以直接在 AGENTS.md 里回答、但没有链接」的细节段落 → 迁出。
3. 保证入口地图永远精简可信。**一份没人愿意读完的入口地图 = 没有入口地图。**

---

## 职责三：维护「关键约定速查表」

把项目里所有「踩过坑才总结出来的强约定」浓缩成 AGENTS.md 里那张表：
**「约定 / 一句话 / 详见」** 三列，每条一句话，绝不展开。

新增约定的门槛（避免表膨胀）：
- 违反过至少一次，或可预见会反复踩
- 能用一句话说清
- 有明确的正例/反例

超过 12 条时，按主题折叠，AGENTS.md 只留分组标题 + 链接。

---

## 职责四：环境差异显式化

预发与线上、本地与 CI 的差异对 AI 是**隐藏地形**——
它排查时可能遇到「明明代码对的，就是不生效」的无法解释现象。

必须写清：
- 差异点清单（配置、开关、数据源、网络、权限）
- 各自的表现是什么
- **排障第一原则：遇到不可解释的现象，先怀疑环境，再怀疑代码**

---

## 自检清单

- [ ] 每条都有「结论」，不是纯现象流水账
- [ ] 每条都有证据（提交哈希或日期），可回溯
- [ ] 强约定已同步进 AGENTS.md 速查表
- [ ] AGENTS.md ≤ 120 行
- [ ] 重复的坑已合并，而不是记两条
- [ ] 测试相关的知识已判断归属：换功能点仍成立 → `testing.md`；否则 → 该功能点的 `tests.md`

---

## 护栏

- ❌ 没有「结论」的条目入库——只记录现象不提炼规则 = 制造噪音；四段式（现象/根因/结论/证据）缺一不可
- ❌ 测试知识写错位置：换功能点仍成立 → `testing.md`；否则 → 该功能点 `tests.md`
- ❌ `AGENTS.md` 超过 120 行；>115 行必须把细节迁出，只留一行摘要 + 链接
- ❌ 速查表条目展开写细节（每条一句话，门槛：违反过或可预见会反复踩）
- ❌ 环境差异靠口头传承——必须显式登记进 `environments.md`
- ❌ 同一个坑记两条而不合并

Next: 写 `AGENTS.md` 前后自查行数；结构性变动联动 `collar-architecture`；沉淀完随提交过门禁。

## 与其他 Skill 的协作

提交关卡三件事之一：
- `collar-changelog` 记**做了什么**
- `collar-runbook` 抽**学到了什么**（本 Skill）
- `collar-specs` 检**代码是否偏离了意图**

另有：`collar-architecture` 产出的环境差异 ADR，由本 Skill 落到 `environments.md`。

# Collar 工程看板

读取遵循 [Collar SDD](../collar-sdd) 规范的项目，把知识库文档渲染成可视化看板。
**只读**——不修改被查看项目的任何文件。

本仓库自身也是 collar-sdd 的下游项目：知识库骨架见 [AGENTS.md](AGENTS.md)，
模板升级走 `sh scripts/collar-sync.sh`，版本见根目录 `VERSION`。

## 为什么做这个

规范把项目知识结构化写进了仓库（业务地图、决策记录、变更时间线、测试文档），
但读起来仍要逐个打开 Markdown。看板把这些文件解析成视图，让项目状态一眼可见。

看板**不做评分**。健康度总分需要规范里没有定义的权重，做出来就是编造的数字。
它只呈现可机械核对的事实，并标明每条事实的依据出处，判断权交给人。

## 快速开始

```bash
cd collar-board
npm start
```

浏览器打开 http://localhost:5173 ，点击左下角「导入项目」，选择规范项目的**根目录**。

必须用 Chrome 或 Edge。目录读取能力（File System Access API）目前只有 Chromium 内核支持，
Firefox 官方立场是反对，Safari 完全不支持。

> 看板通过本地服务访问而非直接打开 `index.html`：
> 浏览器只在安全上下文（https 或 localhost）下提供目录读取能力。

## 授权说明

浏览器在页面关闭后会收回目录访问权限。因此：

- 项目列表会被记住（存在浏览器本地数据库里）
- 重新打开页面后，点一下项目、在系统弹窗里确认一次，即可继续查看
- 这是浏览器的安全机制，无法绕过

看板全程只申请只读权限。

## 六个视图

| 视图 | 回答什么 | 数据来源 |
|---|---|---|
| 总览 | 项目是什么、边界在哪、有哪些待办 | `collar.yaml`、各模块汇总 |
| 业务地图 | 有哪些业务域与功能点，各自什么状态 | `docs/specs/**/spec.md` |
| 在途变更 | 哪些补丁未收敛、提案待审、日落在途、结构缺口——以及各自下一步 | `docs/specs/**`（同 `collar-status.sh` 口径） |
| 决策脉络 | 做过哪些架构决策、各自何时该复审 | `docs/architecture/ADR/`、`principles/`、`docs/wiki/blue-print/` |
| 变更时间线 | 什么时候改了什么、哪些有破坏性 | `docs/changelog/YYYY/YYYY-MM.md` |
| 结构事实 | 哪些地方不符合规范、依据是什么、怎么修 | 全部文档的交叉核对 |

点击任意功能点或决策卡片，会从右侧滑出明细：验收标准、测试点、补丁、日落记录等。

## 结构事实怎么来的

看板核对的每条规则都取自规范原文，不是自己定的：

| 核对项 | 依据 |
|---|---|
| 每个技术方案都有伴生测试文档 | 结构门禁 S2；`docs/specs/README.md` |
| 验收标准与测试点双向对齐 | 结构门禁 S3；约定 C-005 |
| 补丁与主文档的双向指针 | 结构门禁 S5；`docs/specs/README.md`「关键规格一」 |
| delta 四段结构一致性（七类） | 结构门禁 S5（与 `collar-check.sh` 同口径） |
| 现状文档无会话指代词 | 结构门禁 S7 |
| 「已验证」要求实施任务全勾 | feature / patch 模板实施任务节 |
| 工具链装配（scripts / hooks / skills / CI） | 结构门禁 S0；`commit-gate.md` |
| 模板版本（VERSION）与质量门禁占位符 | `collar-sync.sh` 版本机制；`collar.yaml` |
| 收集被截断时显式声明 | 看板「不编造」原则 |
| 补丁累积到阈值应收敛 | `docs/specs/README.md`「patch 的收敛」（3 个） |
| 技术方案超过 90 天未更新 | feature 模板「创建 / 更新」字段口径 |
| 决策记录编号唯一 | 结构门禁 S4 |
| 入口地图不超过 120 行 | 结构门禁 S1；`AGENTS.md` |
| 认领表与变更记录引用的文件存在 | `docs/specs/README.md`、`docs/changelog/README.md` |

看板只读知识库与装配件（`docs/`、`skills/`、`scripts/collar-*`、`scripts/hooks/`、
`.github/workflows/`、`AGENTS.md`、`collar.yaml`、`VERSION`、`README*`），不读源码树。
指向 `src/` 等未读目录的链接不做存在性核对——
看不到的东西不能报「不存在」，那是编造。读取文件数达上限被截断时会显式声明。

## 项目结构

```
collar-board/
├── server.mjs                # 零依赖静态服务（本地开发用）
├── index.html
├── src/
│   ├── parse/                # 解析层：纯函数，不碰 DOM 与文件系统
│   │   ├── markdown.js       #   受限 Markdown 解析（表格 / 标题 / 链接）
│   │   ├── metadata.js       #   文档顶部的「项 | 值」元数据表
│   │   ├── yaml.js           #   collar.yaml 的受限 YAML 解析
│   │   ├── ac.js             #   验收标准编号提取与对齐
│   │   ├── specs.js          #   业务地图：域 / 功能点 / 补丁 / 日落
│   │   ├── decisions.js      #   架构决策与工程原则
│   │   ├── timeline.js       #   变更时间线
│   │   ├── blueprints.js     #   预研蓝图
│   │   ├── findings.js       #   结构事实推导
│   │   └── model.js          #   组装成完整项目模型
│   ├── fs/                   # 文件读取层
│   │   ├── collect.js        #   从目录句柄读出所需文本（只读）
│   │   └── registry.js       #   项目列表持久化与授权检查
│   └── ui/                   # 界面层
│       ├── app.js            #   装配、交互、抽屉
│       ├── format.js         #   格式化与转义
│       ├── styles.css
│       └── views/            #   六个视图
└── test/                     # 测试
```

解析层是纯函数：输入「文件路径 → 文本」，输出模型。
因此可以直接在 Node 里用真实仓库数据测试，不需要浏览器。

## 测试

```bash
npm test
```

测试用同级目录下的 `collar-sdd` 仓库作为真实输入，逐条对照文档实际内容断言。
若该仓库不在同级目录，相关测试会自动跳过。

覆盖三类：

- **解析正确性**：用真实文档验证元数据、验收标准、补丁、决策、时间线的解析结果
- **模块完整性**：相对导入路径必须存在（写错的路径会让页面整个空白）
- **只读约束**：不包含任何文件写入调用，目录选择只申请只读权限

## 已知限制

- **只在 Chromium 内核可用**。其他浏览器无法选择本地目录，需要另做拖拽或上传通道。
- **不自动监听文件变化**。文档改动后需点「重新读取」。浏览器提供的目录监听能力
  （FileSystemObserver）目前是实验性的、尚未标准化，不适合用于正式功能。
- **不做进度与排期分析**。规范文档里没有支撑这类指标的数据，
  硬算只能靠编造，因此不做。

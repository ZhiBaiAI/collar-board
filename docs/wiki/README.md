# docs/wiki/ — 人工自由知识库

> **人工维护**，需要人保障质量的内容放这里。
> **不要让 AI 自动写 wiki** —— 自动沉淀的是事实，人工沉淀的是判断。
> 两者混淆会让知识库失去可信度。

---

## 知识库的两类归属

| 类别 | 归属 | 原因 |
|---|---|---|
| **人工维护** | wiki（这里） | 需要人的判断、品味、调研 |
| **自动维护** | changelog / architecture / runbook | AI 从 git、代码、对话中自动提取 |

---

## 内容分区

| 内容 | 位置 |
|---|---|
| 设计理念、领域知识、竞品分析 | 本目录下自由建文件 |
| **还没定型的方案构思** | [blue-print/](blue-print/README.md) |

---

## 为什么 blueprint 不放 specs

- `docs/specs/` = **正式规格层**（已确认要做、已定型）
- `docs/wiki/blue-print/` = **自由探索层**（还没确认要如何沉淀成 spec 前的基础能力构思）

混在一起会让 AI 把「想法」当「契约」。

## 写作要求

- **外部事实必须附来源链接** —— 调研结论不能凭空生成
- **区分事实与判断** —— 明确标注哪部分是客观信息，哪部分是我们的结论
- **一个主题一个文件** —— 不要写成大杂烩

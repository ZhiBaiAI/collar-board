# 上下文缝补协议

> ## 铁律
> **任何导致上下文异常的研发架构变动，都必须用适合的方式缝补缺损的上下文。**

---

## 为什么需要这份协议

多人协作到一定阶段，一定会为了发布效率，遵循工程范式把某些硬编码
（比如提示词逻辑）迁移到配置平台、DB 或其他持久化介质上。
这在传统研发时代是标准最佳实践（配置与代码分离）。

**但在 AI 研发时代，这是一个隐蔽的陷阱。**

原本 Agent 的行为逻辑写在代码里，AI 一读代码就知道这个 Agent 会怎么干。
现在逻辑挪到了 DB，代码里只剩一个 `configService.load(code)` 的调用框架。
AI 再读代码，就完全不知道这个 Agent 的具体行为了 —— 它会在关键决策上误判，
或者给出那句让人血压升高的话：

> 「但我不知道这个 Agent 的具体行为，请你去对应平台修改。」

**这就是推理链断裂。**
你以为做了工程优化，实际上把 AI 的上下文捅了个窟窿，研发效率断崖式下跌。

> 更根本的认知：**AI 时代，human in the loop 越少效率越高，
> 所以 AI 上下文始终是效率的关键**（注意：是效率，不是质量）。

---

## 缝补三层模型

| 层 | 解决什么 | 手段 |
|---|---|---|
| **能力层** | 让外置内容**可被取到** | 只读 MCP Server / 只读查询接口 |
| **认知层** | 让 AI **知道该去取** | 配套 Skill：何时查 / 怎么查 / 查到怎么用 |
| **锚点层** | 让代码**自带说明** | `//!` 声明式注释（代码即锚点） |

**只有能力层是不够的 —— 工具「能查」不等于 AI「知道该查」。**
两者合起来，AI 才会主动地、按正确锚点地把外置上下文拉回视野。

---

## 标准缝补动作

### 动作一：MCP 只读通道 + 配套 Skill（适用于动态提示词 / 动态配置）

**MCP 侧**：暴露只读查询工具，按锚点取「当前实际生效」的内容。

```
⟨mcp-name⟩ MCP:
  - get_effective_prompt(sceneCode, agentCode)   # 查询当前实际生效的提示词
  - list_prompt_versions(agentCode)              # 版本历史
  - get_effective_config(sceneCode)              # 查询当前生效配置
```

**Skill 侧**：必须明确回答三个问题，缺一不可：

| 问题 | 内容 |
|---|---|
| **何时查？** | 定义触发条件：涉及相关上下文就主动调 MCP，而不是等人提醒 |
| **怎么查？** | 固定调用链（几步、锚点是什么）。锚点通常是 **场景码 + 对象码** |
| **查到后怎么用？** | 解释返回数据的含义，赋能下游推理 |

产出：AI 任何时候都能取到「当前实际生效」的内容，
那句「请你去平台自己改」不会再出现。

### 动作二：环境差异显式声明（适用于预发 ≠ 线上）

在 `AGENTS.md` 的「关键约定速查」里**显式告知 AI 存在环境差异**，
遇到不可解释的问题要优先考虑环境，细节沉淀成 ADR。

> 模板已内置，见 [AGENTS.md](../../AGENTS.md) 第 4 节与 [environments.md](environments.md)。

### 动作三：`//!` 声明式注释保留锚点（适用于脚本 / 平台外置逻辑）

把逻辑外置到脚本平台时，用注释把上下文锚点保留在代码里 ——
**在脚本引擎眼里是普通注释，对平台却是元数据。代码即锚点。**

```
//! name: ⟨脚本名⟩
//! risk: ⟨low|medium|high⟩
//! params: ⟨参数名:类型:含义⟩
//! env: ⟨可执行环境: dev|pre|prod⟩
//! owner: ⟨@谁⟩
```

即便逻辑外置到了平台，AI 读脚本源码仍能从这些声明里知道：
这个脚本叫什么、风险几何、参数是什么、能在哪个环境跑。

## 缝补检查点

在以下时机**必须**执行缝补检查：

| 时机 | 检查者 | 不通过怎么办 |
|---|---|---|
| 架构变动 / 技术选型 | `collar-architecture` | 在 ADR「后果」里登记为技术债，并写明缝补计划 |
| git commit | 提交关卡 | 提醒补缝补；阻塞性差异可拦截 |
| 代码评审 | 人 | 打回，要求附缝补方案 |

## 登记格式

未缝补的项必须显式登记（不允许默默欠账）：

```markdown
| 外置对象 | 外置到哪里 | 缝补方式 | 状态 |
|---|---|---|---|
| ⟨Agent 提示词⟩ | ⟨配置平台⟩ | MCP + Skill | ✅ 已缝补 |
| ⟨运营脚本⟩ | ⟨脚本平台⟩ | `//!` 锚点注释 | ✅ 已缝补 |
| ⟨灰度规则⟩ | ⟨DB⟩ | 未缝补 | ⚠️ 技术债，责任人 ⟨@谁⟩，计划 ⟨日期⟩ |
```

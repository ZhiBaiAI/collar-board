# 模板：MCP 配套 Skill（上下文缝补的认知层）

> 复制本文件到 `skills/⟨项目⟩-query/SKILL.md` 并填空。
>
> 为什么必须有这个 Skill：
> **MCP 提供了「只读可达」的通道（能力层），但工具「能查」不等于 AI「知道该查」。**
> 配套 Skill 提供「何时 / 怎么取用」的协议（认知层），两者合起来才是完整缝补闭环。

# ⟨项目⟩-query — 把外置上下文拉回 AI 视野

## 背景（为什么要查）

⟨模块⟩ 的业务逻辑（如 prompt 内容）**不在代码中硬编码**，
而是通过 ⟨平台名⟩ 动态管理、独立发布。代码里只有调用框架和数据流转。

**不查的后果**：AI 读代码只能看到 `⟨configService.load(code)⟩`，
无法判断该 ⟨Agent/模块⟩ 的实际行为，就会给出那句让人血压升高的话：
「我不知道它的具体行为，请你去对应平台修改。」

## ① 何时查（触发条件 — 主动，不等人提醒）

命中任一即查：
- 需要判断 ⟨模块⟩ 的行为 / 输出 / 边界
- 排查 ⟨相关线上现象⟩
- 修改涉及 ⟨锚点相关字段⟩ 的代码
- 用户问「它现在到底是怎么工作的」

## ② 怎么查（固定调用链）

锚点 = **⟨场景码⟩ + ⟨对象码⟩**，两步定位，不要猜：

1. `⟨list_scenes⟩()` → 拿到 ⟨场景码⟩
2. `⟨get_effective_prompt⟩(sceneCode=⟨场景码⟩, agentCode=⟨对象码⟩)` → 当前实际生效内容
3. （可选）`⟨list_versions⟩(⟨对象码⟩)` → 版本历史，用于对比「改了什么」

示例：
- 查 ⟨示例场景⟩：⟨sceneCode⟩ = `⟨xxx⟩`，⟨agentCode⟩ = `⟨yyy⟩`

## ③ 查到后怎么用

| 返回字段 | 含义 | 怎么用 |
|---|---|---|
| ⟨content⟩ | 当前生效内容正文 | 作为该模块的**真实行为依据**，优先级高于代码里的调用框架 |
| ⟨version⟩ | 版本号 | 判断是否刚发布（新版本 = 近期行为变更的第一嫌疑） |
| ⟨status⟩ | 生效状态 | `draft` 表示**未生效**，不能当真相用 |

## 红线

- ❌ 禁止在未查询的情况下断言该模块的行为
- ❌ 禁止回答「请你去平台修改」—— 查完再说能不能改
- ✅ 查询结果为 `draft` 时，明确告诉用户「当前线上还不是这个版本」

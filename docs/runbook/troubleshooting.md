# 排障剧本

> 由 `collar-runbook` 在 commit 时自动抽取填充，也可随时主动追加。
> **排障第一原则：遇到不可解释的现象，先怀疑环境，再怀疑代码。**

---

## 格式

```markdown
## ⟨故障一句话描述⟩

- **现象**：⟨观测到了什么（含报错原文关键词）⟩
- **根因**：⟨为什么会这样⟩
- **解法**：⟨一步步怎么做⟩
- **预防**：⟨怎么让它不再发生 —— 这条最重要，没有预防的剧本是流水账⟩
- **证据**：⟨提交哈希 / 日期 / 日志链接⟩
```

## 结构门禁报「全绿」但实际没在检查

- **现象**：`sh scripts/collar-check.sh` 全部 ok、退出码 0，但故意造的违规没被拦住。三种形态：
  ① 检查条件依赖「文件已存在」而非「本次变更」，模板自带示范数据让条件恒真；
  ② `git diff --cached --name-only` 对非 ASCII 路径默认输出转义形式
  （`"docs/specs/97_\345\237\237/..."`），以 `^docs/specs/` 开头的前缀匹配全部失效
  ——模板目录名默认含中文，必然命中；
  ③ `2>/dev/null` 吞掉「文件不存在」，骨架被误删时 grep 无输出，检查静默通过
- **根因**：只验证了「通过路径」，没验证「应该失败的路径」。恒真条件、路径编码差异、
  错误吞没这三类缺陷都不会在正常仓库上暴露——**假绿灯比没有门禁更危险**
- **解法**：① 检查改为要求「同一次提交内变更」而非「存在」；
  ② git 命令加 `-c core.quotePath=false`；③ 新增骨架存在性前置检查（S0），缺文件不进 grep
- **预防**：**每次新写或修改门禁后，必须构造一个违规用例确认它会失败**。
  另两条写门禁脚本的硬约束：`find` 输出不要直接进 `for`（按空白分词，含空格路径会误报），
  用 `while IFS= read -r` + heredoc；不要用管道喂 `while`（子 shell 里失败标志传不出来）
- **证据**：`scripts/collar-check.sh`；2026-09-15 二轮复查

## shell 变量后紧跟全角标点导致 unbound variable

- **现象**：`sh` 执行到 `"…$NUM…"` 时报 `NUM…: unbound variable` 直接退出，
  变量明明已赋值
- **根因**：部分 `/bin/sh` 解析器把紧跟变量名的非 ASCII 字符首字节并入变量名，
  `$NUM…` 被当成变量 `NUM…`。中文文案里「变量 + 标点」极常见，故易踩
- **解法**：字符串内变量一律用 `${VAR}` 花括号形式包裹
- **预防**：写含中文的 shell 脚本时统一用花括号，不依赖裸 `$VAR`。
  扫描残留：`\$([A-Za-z_][A-Za-z0-9_]*)(?=[^\x00-\x7F])`（应零命中）
- **证据**：`scripts/collar-check.sh`；2026-09-15

## macOS 上 sed -i 把下一参数当备份后缀

- **现象**：`sh scripts/collar-init.sh --yes` 或 `sh scripts/collar-converge.sh …` 报 `sed: … invalid command code f`（或把脚本参数吃成备份后缀）；认领表示范行还在，或 spec 已合并但 patch 状态仍不是「已收敛」
- **根因**：GNU sed 的 `sed -i 'expr' file` 在 BSD sed（macOS 默认）里会把 `'expr'` 当成备份后缀、把 `file` 当表达式。脚本约定只依赖 POSIX sh，不能假定 GNU sed
- **解法**：就地改文件一律 `awk … > tmp && mv`，与同脚本里清空 changelog、写收敛注释的写法一致
- **预防**：脚本里禁止 `sed -i`。改脚本后在 macOS 上用临时副本跑 `--yes` / 收敛，确认会改文件且不报 sed 错
- **证据**：`scripts/collar-init.sh`、`scripts/collar-converge.sh`；2026-09-20 本机实测 `sed -i '/⟨示例/d' file` 退出码 1

## 通用排查顺序

1. **确认版本** —— 跑的是不是我以为的那份代码
2. **确认配置** —— 生效值是不是我以为的那个值（外置配置需走缝补通道查询）
3. **确认数据源** —— 查的是不是我以为的那个库
4. **确认灰度** —— 当前用户/流量是否命中新逻辑
5. **确认环境差异** —— 见 [environments.md](environments.md)
6. 以上都确认无误，**才开始怀疑代码逻辑**

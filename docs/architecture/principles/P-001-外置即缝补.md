## 原则

**任何导致 AI 上下文异常的架构变动，都必须用适合的方式缝补缺损的上下文。**

## 为什么是不变量

对 Agent 来说，看不到的知识等于不存在。逻辑一旦离开仓库（提示词进平台、配置进 DB、
规则进脚本平台），AI 的推理链就地断裂：它会按仓库里的旧信息推理出与线上相反的结论，
且全程自洽、无从察觉。未缝补的外置不是优化，是把系统性误判埋进后续每一次会话。

## 判定

- **符合**：外置的同时开只读 MCP 通道 / 保留 `//!` 锚点注释 / 登记 [anchor-registry](../../runbook/anchor-registry.md)；
  确实无法缝补的，在 ADR「后果」中显式登记为技术债并写明责任人
- **违反**：提示词迁到平台后代码里无任何锚点、anchor-registry 无对应条目——
  AI 检索仓库时该逻辑不存在

完整协议（缝补方式按外置类型分流）见 [context-stitching.md](../../runbook/context-stitching.md)。

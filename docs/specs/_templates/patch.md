|---|---|

## ① 覆盖范围（Patch → 主文档）

| 项 | 内容 |
|---|---|
| 目标文件 | ⟨同目录下的 `spec.md`⟩ |
| 目标章节 | 「⟨章节名⟩」 |
| **原状态** | ⟨一句话描述被替代的旧方案⟩ |
| **新状态** | ⟨一句话描述新方案⟩ |
| 是否破坏性 | ⟨是 / 否；是则写明迁移方式⟩ |

> ⚠️ **建完 patch 后，必须回到主文档对应章节加反向指针**（见下方第 ⑤ 节），
> 单向指针会造成语义二义性。

## ② 动机

⟨为什么要改。触发原因：缺陷 / 性能 / 需求变更 / 编码时发现更优解⟩

## ③ 改了什么

- **接口**：⟨签名 / 字段 / 行为变化⟩
- **数据**：⟨是否需要迁移，回滚方式⟩
- **配置**：⟨新增或变更的配置项，默认值⟩

## ④ 兼容性

⟨旧客户端 / 旧数据 / 灰度策略如何处理⟩

## ⑤ 主文档反向指针（主文档 → Patch）

在主文档目标章节处**必须**加入以下内容（建 patch 时同步粘贴过去）：

```markdown
> ⚠️ 本段已被 [PATCH-⟨NNN⟩ — ⟨一句话改动⟩](./PATCH-⟨NNN⟩-⟨文件名⟩.md) 取代（生效 ⟨YYYY-MM-DD⟩）。
> 以下仅作历史上下文保留，不代表当前生效实现。
```

## ⑥ 验收标准变更（Delta）

> **四类小节分别对应主文档 §5 的不同操作，收敛时可由 `collar-converge.sh` 机械合并。**
> 没有对应类型的小节整节删除，不要留空标题。
> MODIFIED / REMOVED / RENAMED(FROM) 引用主文档已有的 `AC-N`；ADDED 与 RENAMED(TO) 用新编号，
> patch 自带编号为 `AC-P⟨NNN⟩-N`（与主文档的 `AC-N` 区分开——同一目录下两套编号不能撞车）。
> **同一个 `AC-N` 不许出现在两个小节里**（改了就别删、删了就别改）——结构门禁 S5 会拦。

### ADDED
- [ ] `AC-P⟨NNN⟩-1` ⟨新增的可判定条件⟩

### MODIFIED
- [ ] `AC-⟨N⟩` ⟨替代主文档 AC-⟨N⟩ 的新文本；该编号必须在主文档 §5 真实存在⟩

### REMOVED
- `AC-⟨N⟩` ⟨作废原因一句话⟩

### RENAMED
- FROM: `AC-⟨N⟩` ⟨原编号，必须在主文档 §5 存在⟩
- TO: `AC-P⟨NNN⟩-⟨M⟩` ⟨新编号，必须用 AC-PNNN-N 形（普通 AC-N 会撞主文档编号体系）且在主文档不存在⟩

> **同步要求**：patch 一旦新增或改动了验收标准，必须回到同目录 [`tests.md`](./tests.md)
> 追加/更新对应测试点，并在其「变更记录」留一行——否则 patch 生效了测试还停在旧版本。

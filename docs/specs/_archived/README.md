# _archived/ — 日落归档区

> **这里存放的不是垃圾，是历史上下文。**

---

## 为什么需要这个目录

旧功能下线时，如果直接 `git rm` 掉 spec，那段历史上下文就**永久丢失**了。
未来排查灰度期的线上问题会抓瞎 —— 你不知道旧链路长什么样，
也就无法回答「为什么老用户的行为和现在不一致」。

所以 sunset 的最后一步是**移动到这里**，不是删除。

---

## 规则

| 规则 | 说明 |
|---|---|
| **只进不改** | 归档后的 spec 不再维护，只作为历史事实保存 |
| **保留原路径信息** | 归档时重命名为 `⟨原业务域⟩__⟨功能模块⟩.md`，或在文件头注明原路径 |
| **必须带日落单链接** | 文件头写明「由 SUNSET-NNN 归档，日期，替代方案」 |
| **代码可删，spec 不可删** | 代码删除靠 git 历史可回；spec 是意图，必须留可读文本 |
| **可检索** | 在本文件「归档清单」登记，否则等于没归档 |

## 归档动作（由 `collar-specs` 执行）

1. 把 spec 从 `docs/specs/NN_[业务地图]域/NN_功能/` 移动到本目录
2. 文件头加归档标记：

```markdown
> 🗄 **已归档** —— 由 [SUNSET-NNN](../NN_%5B业务地图%5D域/NN_功能/SUNSET-NNN-xxx.md) 于 ⟨YYYY-MM-DD⟩ 归档。
> 原路径：`docs/specs/NN_[业务地图]域/NN_功能/`
> 替代方案：⟨链接 / 「无替代，直接下线」⟩
> 以下内容仅作历史上下文，不代表当前生效实现。
```

3. 在本文件「归档清单」追加一行
4. 更新 `docs/specs/README.md` 的站点地图与认领表（移除该模块的在维状态）
